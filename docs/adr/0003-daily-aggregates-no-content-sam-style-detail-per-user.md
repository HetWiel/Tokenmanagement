# Daily aggregates only, never content; per User only SAM-style facts

Token Management stores AI Consumption as daily aggregates per User or Workload, per AI Tool and per model. It never stores prompt or response content, and keeps no per-call records. Users are shown by name to everyone with access, as is normal in SAM. Per User, however, the tool shows only SAM-style facts: which seats they hold, whether they are active, and the date of their last activity. AI Token volumes and Estimated Cost are shown per Cost Centre, per Workload and per AI Tool, never per User. This keeps every Optimization Opportunity actionable without turning the tool into an AI-usage leaderboard of employees, which is what works councils object to. We rejected per-call records (a GDPR and works-council liability), pseudonymised Users (they make Idle Seats unactionable for the Client) and full per-User volumes (they look like productivity monitoring). Collecting or showing finer data later would mean renegotiating with every Client, so this is hard to reverse.
